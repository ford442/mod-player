# Audio worklet assets

Self-hosted worklet and libopenmpt assets served from `public/worklets/` (copied to `dist/worklets/` on build).

## Production JS worklet path (default)

| File | Role |
|------|------|
| `openmpt-worklet.js` | `AudioWorkletProcessor` — renders module audio in `process()`. **Generated** (`// generated — do not edit` header) from `audio-worklet/js/openmpt-processor.ts` by `npm run build:js-worklet` (esbuild) — edit the TS source, not this file. See `docs/WORKLET_AUDIO_BUG.md` § "Compiled TypeScript worklet source (#435)". |
| `libopenmpt-worklet.js` | Emscripten **glue** for libopenmpt 0.8.4 (classic script, ~100 KB). Generated by `npm run build:js-libopenmpt`. |
| `libopenmpt-worklet.wasm` | The **real WebAssembly** binary (~1.7 MB, `\0asm` magic, no SIMD, native wasm exceptions). Same build, same bytes. |

`libopenmpt-worklet.{js,wasm}` are tracked in git (like the JS processor) so deploys need no emsdk. They are
built by `scripts/build-js-libopenmpt.sh` and described by the generated manifest
`audio-worklet/js/libopenmpt-worklet.generated.json` (sizes, SRI hashes, a content-hash cache key, the emsdk
that built them). **One pair serves every JS-engine consumer** — nothing replaces `globalThis.WebAssembly`:

| Consumer | How it loads the pair |
|----------|-----------------------|
| AudioWorklet | main thread `fetch`es both, validates them (`utils/workletLibAssets.ts`), posts `initLib {scriptText, wasmBytes}` |
| Main thread | `<script src=…?v=…>` injected into `index.html` by `vite-plugins/libopenmptHtml.ts` (SRI-pinned; `Module.locateFile` versions the `.wasm` too) |
| Parser worker | `new Function(glue)` + `locateFile` → the same `.wasm` (`utils/libopenmptAssets.ts`) |

Every request carries `?v=<content hash>` so a browser/service-worker cache can never pair a new glue with an old
`.wasm` (their import tables are minified per build).

### Load sequence (worklet)

1. Main thread: `audioWorklet.addModule(…/openmpt-worklet.js?v=N)` (`hooks/useWorkletLoader.ts`; `?v=` is a content hash of the compiled processor, from `audio-worklet/js/worklet-version.generated.json` — no manual bump needed).
2. Main thread creates `AudioWorkletNode` with processor name `openmpt-processor`.
3. Main thread fetches `libopenmpt-worklet.js` **and** `libopenmpt-worklet.wasm` in parallel and rejects anything wrong *here* (HTML 404 body, missing `\0asm` magic, a stale wasm2js glue).
4. Main thread `postMessage({ type: 'initLib', scriptText, wasmBytes }, [wasmBytes])`, then `setRenderParam` (interpolation) and `load`.
5. Worklet evaluates the glue via `new Function` (classic-script scope), seeded with `Module.wasmBinary` (the worklet scope has no `fetch()`), **waits for `onRuntimeInitialized`** (`audio-worklet/libRuntimeReady.ts` — never infer readiness from `_openmpt_*` being defined: newer emsdk defines lazy stubs at eval time), then accepts `load` / `play` / `seek`.

There is **no** wasm2js path: `initLib` without `wasmBytes` is rejected. `npm run verify:wasm` / `verify:js-libopenmpt` fail on HTML-as-wasm and on a wasm2js glue.

### Rebuilding the pair

```bash
source /path/to/emsdk/emsdk_env.sh      # emsdk 3.1.51 (CI pin); newer emsdk also works
npm run build:js-libopenmpt             # → libopenmpt-worklet.{js,wasm} + manifest
npm run verify:js-libopenmpt            # static checks + boots the glue exactly as the worklet does
```

Flags worth knowing (see the header of `scripts/build-js-libopenmpt.sh`): **wasm exceptions** (`-fwasm-exceptions`;
a corrupt upload must return `NULL`, not abort the shared worklet runtime), **no SIMD** (measured no win — see
`docs/planning/native-engine-bench-notes.md`), `INITIAL_MEMORY=32 MiB` with growth (the wasm2js glue reserved
~512 MiB), the whole libopenmpt C API exported, and `stringToUTF8` deliberately **not** exported (the app's
polyfill has a different signature). The build uses its own libopenmpt tree under `vendor/…-jsengine-<variant>-emsdk<ver>`.

### Interpolation

The JS worklet defaults to **Sinc+LP (8)**: with real wasm it costs a few percent of the 128-frame quantum budget even
at 64 channels (the wasm2js glue could only afford cubic). Opt down with `?interp=4` (or
`localStorage.xasm1_js_interp=4`) on weak devices; valid values are 1, 2, 4, 8. The choice is kept across module reloads.

## Engine

The JS worklet is the only engine; when AudioWorklet or its WASM init fails, the app falls back to a main-thread
`ScriptProcessorNode`. The optional native C++ worklet (`openmpt-native.*`, `?engine=native`) was retired — see
`docs/ADR-native-engine.md`.

**No WebAssembly snapshot:** the main-thread libopenmpt is the same real-WASM build as the worklet's, so it never replaces `globalThis.WebAssembly`. (`index.html` used to snapshot the real API as `window.__NATIVE_WEBASSEMBLY__` because the old wasm2js `libmpt/libopenmptjs.js` swapped in a stub whose `Memory()` was never shared — that whole workaround is gone.)

**projectM PCM chunks** are posted by the JS worklet (`projectm-pcm`) → `broadcastPcmBlock`.

**Performance capture (MediaRecorder)** taps the one shared `AudioContext` (`utils/audioContextFactory.ts`). See `docs/EXPORT.md`.

## CI / hygiene

```bash
npm run verify:wasm          # every *.wasm under public/ and dist/ must have \0asm magic (and libopenmpt-worklet.wasm must exist)
npm run verify:js-libopenmpt # the real-WASM JS engine pair: files, exports, manifest, boots + renders + survives corrupt input
```

- **Every PR:** `npm run preflight` (`lint-and-build`), shellcheck of the build script + JS-processor guard (`ci.yml` → `build-scripts`), JS `playhead-smoke`.
- **Path-filtered PR / push:** `js-libopenmpt-rebuild` rebuilds the pair with emsdk 3.1.51 when its inputs change and fails if the committed files drift from a fresh build.

Never commit failed download bodies (404 HTML) as `.wasm`.
